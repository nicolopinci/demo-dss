GURU · ENLIT 2026

Simulation only — not the live GURU system.

This page demonstrates the intended interaction using a real multilingual neural retrieval model and pre-existing benchmark question–answer pairs. It does not generate answers, run the full GURU orchestration system, perform live energy analysis, operate devices, or validate the full system’s capabilities.

  1. Type a question and press Enter or the pink arrow.
  2. A multilingual MiniLM model embeds your question locally and compares it with benchmark questions in the detected or selected language using cosine similarity. The selected question replaces your input.
  3. The selected question’s stored answer is displayed verbatim. Check the replacement: a semantic match may still change the meaning of your original question.

Answers may be inaccurate, outdated, or inappropriate for your circumstances. They are reproduced without verification and should not be relied on as authoritative advice. The model is multilingual, but retrieval is restricted to your question’s language. Stored answers are not translated or fact-checked. Exact-equivalent questions are matched directly within the selected language; duplicates use their first row in that language. Other queries select the highest cosine similarity without a minimum threshold. If an explicit climate-zone letter is recognized and that zone exists in the benchmark, candidates must also match that zone. If none exist in the requested language, the page reports that no eligible answer is available. Similarity is not a probability of correctness.

Use Example questions to browse the active dataset. Enter sends; Shift+Enter adds a new line. Your chat history lasts only for this tab session and is cleared on reload.

Primary data source: JouleQA CSV in this repository ↗

If the repository CSV is missing, invalid, or blocked when opening this HTML directly from your computer, the page uses a labelled copy of the original user-uploaded benchmark. This fallback has not been verified against the repository CSV. The active source is shown above the chat and beside each answer.

All model inference and matching run in a Web Worker in your browser using the CPU (WebAssembly). Questions are not sent to an inference service. The page and CSV load from your site, the JavaScript library/runtime from jsDelivr, and the model from Hugging Face and its download hosts. These hosts receive normal asset-download requests. There is no analytics code.

Answer language: Auto-detect uses the local ELD 2.1.0 language detector, loaded from jsDelivr. Both exact and semantic searches are restricted by the CSV’s Language column before ranking. This relies on the benchmark language labels being correct. No answer from another language is silently substituted.

For short, mixed-language, or ambiguous input, select the question language explicitly. The selector overrides automatic detection. If the detected language has no benchmark entries, the demo displays a notice and no answer. Serbian in Latin script may require manual selection. Choosing an example sets its language; a new chat returns to Auto-detect.

Model: paraphrase-multilingual-MiniLM-L12-v2, an 8-bit quantized ONNX model, with Transformers.js 3.8.1. It produces normalized 384-dimensional embeddings using mean pooling and up to 128 tokens per question. Retrieval is semantic cosine similarity, not the previous weighted keyword score.

First visit: the model download is about 118 MB, plus tokenizer and runtime files. Encoding the benchmark may take a few minutes on CPU; progress is shown above the chat. The interface remains responsive. If loading fails, semantic search is disabled until you retry; it does not silently switch to keyword matching.

Local cache: model assets may be cached by the browser. Benchmark embeddings are cached in IndexedDB using a fingerprint of the model configuration and complete ordered question list. Changing questions causes re-encoding; changing only answers reuses embeddings with the new answers. User questions and conversation history are not saved in this cache. Clearing the site’s browser data removes its caches.

Hosting: upload index.html and jouleqa_benchmark.csv side by side in the root of your GitHub repository (filenames are case-sensitive), then enable Settings → Pages → Deploy from a branch → main → / (root). No backend, Python, local package installation, GPU, API key, or build step is needed. Internet access is required to download the library and model assets when they are not cached. Use a current browser with WebAssembly and module-worker support. Open the published GitHub Pages URL to load the repository CSV. If you open this HTML directly from your computer, browser file-access restrictions may cause it to use the bundled fallback instead.
